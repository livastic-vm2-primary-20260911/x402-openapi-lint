Usage for autonomous clients

Use https://vm5-openapi-x402.onrender.com as the permanent primary API host. For the VM5 backup Quick Tunnel only, resolve the current URL from the public live.json file alongside this page. The paid request takes a JSON envelope containing one spec string. Invalid documents are rejected without payment; valid requests return an x402 HTTP 402 challenge until the client supplies a signed authorization.

GET /v1/sample       free, complete lint example
GET /v1/docs         free, terms, schema and receiving wallet
POST /v1/lint        paid, 0.02 USDC on Base

Content-Type: application/json
{"spec":"openapi: 3.0.3\ninfo: {title: Demo, version: '1'}\npaths: {}"}

No PAYMENT-SIGNATURE → HTTP 402 (no money collected)
Valid signed x402 request → verification/settlement by external facilitator, then structured Redocly findings.

Machine clients: fetch live.json for apiBase and POST the body to apiBase + /v1/lint. The VM5 backup tunnel may change after server restarts, but the Render address is stable.

Safety and payment limitations

This is a technical pilot. No live USDC payment or end-to-end settlement was made while developing this service; the quote format and local validator tests are proven but settlement remains unverified. We publish actual receipts only if they can be checked on-chain.

Do not submit passwords, API tokens, private repository contents, wallet seeds or customer records. The application processes specs locally in temporary files; external providers including Cloudflare and the payment facilitator may log transport metadata. No uptime SLA or refund automation is promised.

A lint failure can be a successful result: the paid output is a factual report of schema defects, not a guarantee that the supplied API is valid. Results are not a security certification.
